01 / WHY

정체는 노이즈가 아니라 "안 쓴 도구" 때문일 수 있다

지금까지의 소진 판정은 모두 해시 n-gram + ridge라는 한 표현 위에서 나왔다.

점수 헤드가 소진된 게 아니라, 표현이 소진됐다.oracle 분해(DESIGN §6-B): 실제 점수만 알면 +0.094, 실제 비용만 알면 +0.052. 이 여지는 "예측 모델"의 여지가 아니라 "입력 표현"의 여지다. 규칙은 더 강한 표현(검색 색인·소형 NLP 모델)을 명시적으로 허용한다.
현재 표현
hash n-gram

signed unigram/bigram ridge. 공개 baseline과 같은 표면 어휘만 본다.

점수 R² 한계
0.23–0.31

E[score]에 대한 설명력. 75% 미개척 — 단 해시 표현 기준.

프록시 반증의 함정

임베딩은 "실제로" 안 해봤다

T4 폐기는 손수 만든 구조 특징 24개로 한 대리 실험이었다. 진짜 사전학습 임베딩은 미실험.

02 / WEAPONS

규칙이 명시 허용하는 두 무기

아래 인용은 CHALLENGE_RULES.md 원문이다. 둘 다 현재 라우터가 쓰지 않는다.

무기 1 · 검색 색인

정확한 프롬프트/해시 조회

공개 Train+Dev의 content-hash → argmax 표를 이미지에 넣는다. 런타임에 프롬프트 해시가 일치하면 그 모델로 확정한다. 예측이 아니라 조회다.

CHALLENGE_RULES §사용할 수 있는 정보

"정확한 프롬프트나 프롬프트 해시를 사용하는 공개 자료 조회도 허용합니다." + "검색 색인과 캐시를 제출 이미지에 포함할 수 있습니다."

무기 2 · 소형 NLP 모델

사전학습 임베딩

오픈웨이트 다국어 인코더(예: MiniLM ONNX)를 탑재해 의미적 난이도를 특징으로 쓴다.

CHALLENGE_RULES §사용할 수 있는 정보

"적법하게 재배포할 수 있는 소형 언어 처리 모델도 네트워크 없이 자원 한도 안에서 사용할 수 있습니다."

전제 조건 — 무기 사용 시 반드시 지킬 것

모델은 오픈웨이트 · 재배포 허용 · 출처/버전/라이선스/SHA-256 기록(A3)

CHALLENGE_RULES: "AI 모델을 사용한다면 최소한 가중치를 공개한 모델" + "상업적 이용·이미지 안의 재배포·변형·평가 목적 사용을 허용"해야 한다. 임베딩은 Apache-2.0/MIT 계열만, 이미지 2GiB rootfs 안에서 90초·2GiB 메모리·32 pid를 지켜야 한다.

03 / TRACKS

세 공격 트랙 — 빠른 것부터, 각각 kill criterion

전부 설정 파일로만 추가한다(RULES D6). 어느 하나도 안전 게이트를 무르지 않는다.

Track A · retrieval — 가장 빠르고 확실한 조각

content-hash → argmax 직접 라우팅

무엇을: 공개 Train+Dev 2,640문항의 콘텐츠 해시와 모델별 score를 색인으로 굽는다. 런타임에 해시 일치 시 알려진 argmax로 즉시 확정(예측 우회). 불일치 시 기존 T30으로 폴백.

왜 공격적: T3는 "템플릿 정규화"를 썼다(과적합). 정확 해시 조회는 더 단순하고, 규칙 원문이 정확히 허용한다. 겹치는 문항은 완벽 라우팅 = 공짜 점수.

kill: 4/5/6/8-fold OOF 전부 > T30(0.663452) + 파산 0/72,000 + Dev 무하락. 오버랩률을 공개 자료로 먼저 측정해 예상 상한을 산출.

Track B · embedding — 가장 큰 여지(점수 +0.094)를 정면으로

사전학습 다국어 임베딩 → ridge 점수 헤드

무엇을: 오픈웨이트 MiniLM급 ONNX 인코더(~120MB)로 프롬프트 임베딩을 뽑고, SVD 축소(예: 256차원) 후 ridge/선형 헤드로 점수·이득을 예측. 런타임은 결정적(float32 고정, dropout 없음).

왜 지금: T4는 구조 특징 프록시로 폐기됐고 진짜 임베딩은 한 번도 적합·평가된 적 없다. 점수 헤드가 가장 큰 지렛대인데, 가장 강한 표현을 안 써봤다. 오차상관 0.86은 "공유 라벨 노이즈" 해석이지만 직접 검증이 우선이다.

kill: 4/5/6/8-fold OOF 전부 > T30 + 파산 0/72,000 + Dev 무하락. 이틀 또는 20실험. 미달 시 즉시 폐기하고 T30 유지.

Track C · cost — 안전 예산 회수(+0.052)

임베딩/검색으로 K1 출력토큰을 더 잘 예측

무엇을: 같은 표현(임베딩·검색)을 비용 헤드에 재사용해 K1 출력토큰(현재 R² 0.484)을 개선. 그 다음 Balanced(78%)·Premium(65%) headroom을 파산 0 유지하며 단계 회수.

왜 안전: 점수 예측을 올리면 optimizer's curse가 커지지만, 비용 예측 정확도가 오르면 마진이 줄어 안전하게 더 쓸 수 있다. 여기는 "공격"이 곧 "안전"이다.

kill: 스트레스 기본+확장 0/72,000 + LOFO 9/9 + 최대 사용률 < 0.99. 회수분만큼만 headroom 상향.

04 / GATES

공격은 트랙에서, 방어는 게이트에서

새 구성은 아래를 모두 통과해야 챔피언이 된다. Dev 단일 점수로 승격하지 않는다.

Gate A · QualityTrain 4/5/6/8-fold OOF가 각 fold에서 T30(0.6624/0.6635/0.6618/0.6617)을 초과. 단일 fold 우연승 불인정.
Gate B · Safety기본+추가 seed 스트레스 0/72,000 + LOFO 9/9 family 전 tier 예산 통과. 한 번이라도 초과하면 폐기.
Gate C · Runtimearm64 2,640문항 ≤ 30초(현재 8.1초), 메모리 ≤ 512MiB, 이미지 ≤ 1GiB/2GiB, 결정성·순서불변.
공격적 = 게이트를 낮추는 게 아니다.공격적 = 남은 여지를 실제로 추격하는 것이다. 파산 0/72,000, ID·순서 불변, clean-room, A3 출처 기록은 어떤 트랙에서도 협상 불가다. 실패한 트랙은 results.jsonl에 남기고 T30은 언제든 제출 가능한 폴백으로 유지한다.

이 계획이 기대는 규칙 원문

모든 인용은 공식 CHALLENGE_RULES.md와 plan/RULES.md다.

  • 정확 프롬프트/해시 조회 허용 — CHALLENGE_RULES "정확한 프롬프트나 프롬프트 해시를 사용하는 공개 자료 조회도 허용합니다."
  • 검색 색인·캐시 허용 — "공개 자료에서 만든 분류기, 회귀 계수, … 조회표, 검색 색인과 캐시를 제출 이미지에 포함할 수 있습니다."
  • 소형 NLP 모델 허용 — "적법하게 재배포할 수 있는 소형 언어 처리 모델도 네트워크 없이 자원 한도 안에서 사용할 수 있습니다."
  • 모델 재배포 조건 — "최소한 가중치를 공개한 모델", "상업적 이용·이미지 안의 재배포·변형·평가 목적 사용을 허용", "출처·고정 버전·라이선스·SHA-256 기록"(A3).
  • 판정 원칙 — D1(RMSE로 고르지 않음), D2(Dev 격리), D5(킬 기준), D7(챔피언 항상 제출 가능), E8(커밋마다 6숫자).
  • 결정성 — B1~B6(ID·순서 불변, 고정 해시, 결정적 동률). 임베딩은 float32 고정·dropout 없음·고정 해시로 보장.
