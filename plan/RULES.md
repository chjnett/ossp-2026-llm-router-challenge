## A. 실격 방지 (위반 = 전체 제출 실격)

**A1. 프롬프트와 등급 외에는 아무것도 보지 않는다.**
모델 선택 함수의 시그니처는 `select(text: str, tier: str)` 형태로 고정한다.
`episode_id`, `split`, `challenge_id`, 배열 인덱스는 **타입 수준에서 전달 불가**하게 만든다.
"실수로 못 쓰게" 만드는 것이지 "안 쓰기로 약속"하는 게 아니다.

**A2. 런타임 네트워크 접근 0.**
`docker run --network none`으로 통과하지 않은 코드는 머지 금지.
런타임 중 다운로드·외부 추론 호출·비공개 경로 의존 전부 금지.

**A3. 이미지에 넣는 모든 파일은 출처·고정 버전·라이선스·SHA-256을 먼저 기록한다.**
기록 없이 파일을 추가하지 않는다. 순서는 항상 `기록 → 추가`.
허용 라이선스: `Apache-2.0`, `MIT`, `BSD-2-Clause`, `BSD-3-Clause`, `ISC`, `0BSD`,
`BSL-1.0`, `Zlib`. 자료·문서는 조건 충족 시 `CC-BY-4.0`, `CC-BY-SA-4.0`.
AI 모델을 쓰면 **최소 open-weight**여야 하고 가중치를 공개 위치에 게시해야 한다.

**A4. 공개 Train/Dev와 공개 비용 정책 외의 정보는 쓰지 않는다.**
비공개 평가 자료·평가 실행 결과·프롬프트 밖 메타데이터 추정 시도 금지.

**A5. 원본 저장소에 PR을 보내지 않는다.**
`CONTRIBUTING.md`가 외부 기여를 받지 않는다고 명시. fork에서만 작업한다.

## B. ID·순서 불변성 (위반 = 자동 채점 중단, 수동 검토)

> 근거: `OPERATIONS.md` — 감사 재실행은 **생략 옵션이 없고**, 오케스트레이터가
> **모든 문항의 ID를 재배정하고 순서를 따로 섞은** 입력으로 한 번 더 돌린다.
> 선택이 다르면 `review_required` → 종료코드 5.

**B1. 같은 프롬프트 + 같은 등급 → 항상 같은 model_id.**
ID·순서·배치 내 위치가 바뀌어도 비트 단위로 같아야 한다.

**B2. 배치 집계는 순서 불변 연산만 쓴다.**
합산은 `math.fsum` 또는 정수/`Decimal`. 누적 `+=`나 `np.sum`을 예산 판정 경로에 쓰지 않는다.
정렬이 필요하면 **콘텐츠 파생 키**(프롬프트 해시)로만 정렬한다. 인덱스 정렬 금지.

**B3. argmax 동률은 결정적으로 깬다.**
모델 우선순위를 고정(`ax31-light` < `ax31` < `axk1-think`)하고, 동률이면 항상 싼 쪽.
같은 특징값 그룹은 통째로 승격하거나 통째로 유지한다 — 그룹을 쪼개지 않는다.

**B4. 해시는 고정 해시만 쓴다.**
Python 내장 `hash()` 금지(`PYTHONHASHSEED`로 프로세스마다 달라짐).
`hashlib.blake2b` 또는 직접 구현한 FNV 등 고정 알고리즘만.

**B5. 난수·시각·환경변수·로케일에 의존하지 않는다.**
`random`, `time`, `os.environ`, `datetime`을 결정 경로에서 호출 금지.

**B6. ID 셔플 + 순서 셔플 property 테스트를 CI에 넣는다.**
공개 Train/Dev 전체에서 1비트라도 다르면 실패로 처리한다.

## C. 예산 (위반 = 해당 등급 0점, 가중 최대 −0.40)

**C1. 예산 초과는 0점이다. 점수 몇 %p와 절대 교환하지 않는다.**
Dev 실측: 예산 1.25→1.15로 낮춰도 oracle 손실은 0.014뿐. **안전은 거의 공짜다.**

**C2. 안전은 사용률 마진이 아니라 비용 추정기에서 나온다.**
실측: Premium을 사용률 0.90으로 낮춰도 실제 비율 4.18로 초과했다.
원인은 optimizer's curse — allocator가 **비용이 과소추정된 문항을 우선 선택**한다.
따라서 비용 헤드는 평균이 아니라 **상방 분위(τ≈0.75)** 로 학습하고,
로그공간 예측에는 Jensen 보정을 넣는다.

**C3. K1에는 문항별 하드 캡을 건다.**
예측 출력토큰이 상위 분위를 넘는 문항은 λ와 무관하게 `axk1-think` 후보에서 제외한다.
K1 비용은 light 대비 5.2배~566배(중앙값 23.5배)로 꼬리가 두껍다. 마진으로는 못 막는다.

**C4. 파산 게이트는 "기대값"으로 판정한다 — 파산확률 ≤ 0.25% 허용.**
분포이동 스트레스 **N = 2,000회 × 6시나리오**, 온건(Dirichlet conc=5)·극단(conc=0.7)
양쪽, 그리고 leave-one-family-out 시나리오에서 **등급별 파산률 ≤ 0.25%(12,000회 기준
초과 ≤ 30회)**를 통과해야 제출 후보가 된다.
> 2026-08-16 개정(2차): 경쟁 분석(iSN-ELR·leelang7 등 활발한 팀 확인) 후 EV 우선으로
> 상향했다. 공식 규칙은 "초과 = 그 등급 0점"일 뿐 "파산확률 0"을 요구하지 않는다.
> 등급 파산 손실(가중 ≈ −0.216) × 0.217%(T38) = 0.00047 < 기대 이득 0.0026이므로
> 0.25% 허용이 정당화된다. 채택 구성 T38은 스트레스 26/12,000(0.217%), LOFO 3.60.
> 단, 스트레스 모델은 실제 비공개 분포의 근사일 뿐이다. 0.217%는 모델 추정치이며,
> 비공개셋이 더 가혹하면 실제 파산률은 이보다 클 수 있다.

**C5. 예측기·특징·정책을 바꾸면 안전 보정을 **자동으로** 다시 돌린다.**
실측: 점수 예측이 좋아지면 고이득=고비용 문항을 더 확신하고 골라 **예산 위험이 올라간다.**
안전 설정은 예측기에 종속이다. 손으로 유지하지 말고 파이프라인에 넣는다.

**C6. 모든 실험 기록에 등급별 (점수, **실제 비용 비율**, 한도 대비 여유)를 남긴다.**
점수만 적힌 결과는 결과가 아니다.

## D. 방법론

**D1. RMSE로 모델을 고르지 않는다.**
선택 기준은 오직 **오프라인 하네스의 등급별 점수 + 예산 통과 여부 + 가중 최종**이다.
`score`는 2~4회 생성의 평균이라 표본노이즈 sd가 0.12~0.15다. RMSE 개선이
결정 개선을 뜻하지 않는다. R²는 진단용 보조 지표로만 본다.

**D2. 후보 선택 중에는 Dev를 학습에 섞지 않는다. 최종 재적합은 예외다.**
회귀계수·트랙·임계값을 고르는 동안 회귀계수는 Train에서만 학습하고 Dev는
독립 확인용으로 남긴다. 챔피언과 모든 안전계수를 동결한 뒤에는 더 이상 결과를
보고 결정을 바꾸지 않는 조건으로, 제출 아티팩트만 규칙상 허용된 공개
Train+Dev 전체에 재적합한다. 재적합 후 공개 outcome은 사전에 고정한 스트레스의
이진 통과/실패 판정에만 쓰고 새 계수나 임계값을 고르지 않는다. 실패하면 기존
Train-only 아티팩트로 폴백한다.

**D3. 어떤 주장도 재현 가능한 실험 없이는 설계에 반영하지 않는다.**
가설은 가설이라고 표시한다. 실험 결과는 append-only JSONL에 남긴다.
"~일 것이다"로 시작하는 문장은 TODO의 실험 항목이지 설계 결정이 아니다.

**D4. 대안가설을 기각할 수 없는 실험으로 결론 내지 않는다.**
"표현을 바꾸면 뚫린다"를 같은 표현공간의 선형변환으로 검증하려던 시도가 실제로 있었다.
검증 설계가 결론을 지지할 수 있는지 먼저 확인한다.

**D5. 트랙에는 킬 기준과 마감을 함께 정의한다.**
기준 미달이면 미련 없이 버린다. 기한 없는 탐색은 시작하지 않는다.

**D6. 실험은 설정 파일로 한다. 코드 분기를 늘리지 않는다.**
새 아이디어가 코드 수정을 요구하면 그건 계약이 잘못 그어진 것이다.
파이프라인 6단계(`[F] [Q] [C] [G] [A] [S]`)의 입출력 계약은 고정하고 구현만 갈아끼운다.

**D7. 챔피언은 항상 제출 가능한 상태로 유지한다.**
새 구성은 ① CV 가중 최종이 챔피언 초과 ② 파산 게이트 통과, **둘 다** 만족할 때만 승격한다.
이 규칙이 있으면 실패한 실험의 비용이 0이 되고, 방향 전환이 판단이 아니라 순위표를 읽는 일이 된다.

**D8. 버린 트랙의 결과도 지우지 않는다.**
`results.jsonl`은 append-only다. 나중에 조건이 바뀌면 되살릴 수 있어야 한다.

## E. 엔지니어링

**E1. 어떤 예외도 등급을 죽이지 않는다.**
최상위 `try/except`로 전부 흡수하고 all-light로 폴백한다. 크래시 = 등급 0점.
프로세스 시작 직후 all-light 결정을 메모리에 확보한 다음에 예측을 시작한다.

**E2. 워치독을 건다.**
경과 시간이 한도의 60%(54초)를 넘으면 남은 문항을 all-light로 마감하고 즉시 출력한다.

**E3. 출력은 원자적으로 쓴다.**
같은 디렉터리 임시 파일 → `os.replace`. 권한 `0644`.
출력 볼륨 루트에 `submission.json` **외의 어떤 파일·디렉터리·링크도 만들지 않는다**.

**E4. 로그를 거의 찍지 않는다.**
stdout/stderr 각 총 1 MiB 초과 = 실행 실패. 성공 메시지 한 줄이면 충분하다.
진단 로그는 환경변수가 아니라 **별도 오프라인 스크립트**로 뽑는다(A1·B5 위반 방지).

**E5. 성능 게이트: 2,640문항 기준 컨테이너 실행 ≤ 30초.**
공식 참고치는 hash-regex가 7.3초, `memory.peak` 76.66 MiB, `pids.peak` 6 (한도 90초·2 GiB·32개).
비공개셋 크기를 모르므로 3배 여유를 남긴다. 메모리는 512 MiB 이내로 유지한다.

**E6. `VOLUME` 선언 금지.** 선언하면 실행 전에 접수 거부된다(재시도 없음).

**E7. 이미지 크기 한도를 접수 전에 확인한다.**
압축 계층 합계 1 GiB, rootfs 겉보기 2 GiB. 초과 시 **실행조차 안 하고 거부**된다.

**E8. 커밋마다 공개 Train·Dev 양쪽에서 `self-check`를 돌리고
6개 숫자(3등급 × 점수/비율)를 커밋 메시지에 남긴다.**

**E9. 조직위 검증 명령을 CI에 넣는다.**
`python3 -m unittest discover -s tests -p 'test_*.py'`, `ruff check .`, `reuse lint`.
새로 추가하는 원본 파일에는 SPDX 헤더를 붙인다.

## F. 제출

**F1. all-light(가중 0.619)보다 낮은 구성은 제출하지 않는다.**
항상 동작하는 폴백 브랜치를 마지막까지 유지한다.

**F2. 2026-08-25 24:00에 이미지를 동결한다.**
이후 라우터 코드 변경 금지. 문서·결과보고서·제출 JSON만 손댄다.

**F3. 제출 순서를 지킨다.**
① 코드 커밋 → ② 그 커밋에서 `linux/arm64` 이미지 빌드 → ③ 레지스트리 push,
전체 다이제스트 확보 → ④ `submission-ossp-skt.json`을 **별도 커밋** →
⑤ 그 커밋의 `tree/<40자리 SHA>` 스냅샷 URL을 결과보고서에 기재.
이미지 참조는 태그가 아니라 `repository@sha256:<64자리 소문자>`.

**F4. 저장소는 제출 시점부터 심사 종료까지, 수상 시 5년간 공개 유지.**

**F5. 결과보고서에 AI 모델 항목을 채운다.**
이미지에 AI 모델을 안 넣으면 `해당 없음 — 실행 이미지에 AI 모델을 탑재하지 않음`.
AI 코딩 도구 사용 범위도 기재한다. SBOM·데모 영상 URL도 요구 항목이다.
