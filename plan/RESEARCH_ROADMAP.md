# 경쟁자 아이디어 분석 + 향후 연구 로드맵 (2026-08-26)

OSSP 2026 LLM Router Challenge에서 추적한 45개 fork 중, 제출 단계·활발히 진행한
18개를 클론해 분석했다. 아래는 그 아이디어의 체계적 정리와, **이를 바탕으로 한
향후 연구 방향**이다. 우리가 실측으로 검증한 것(✓ 기각)과 미검증(개인 연구
후보)을 구분했다.

---

## A. 경쟁자 접근법 분류 (클론 분석 결과)

| 접근법 | 경쟁자 예 | 요지 | 우리 입장 |
| --- | --- | --- | --- |
| **① 의미 임베딩 기반** (fine-tuned E5 + ONNX 런타임) | **Diwoni** (train-only dev 0.7068) | 해시 대신 E5 의미표현 + Qwen 교사증류 + ONNX 49~64s | **최대 이득원. 재현엔 fine-tune+교사증류 총공 필요** |
| **② 확률/승률 분류 + regret 가중** | **Seosamo** | LightGBM 승률 이진분류, per-attempt explode, regret 가중 | 실측: 우리 ridge에선 악화. 별도 모델링으로 연구 |
| **③ 토큰 기반 비용 예측** (output/input token → cost 유도) | **Seosamo** (output-token quantile) | 출력토큰=지배 비용을 직접 예측, cost 유도 | 실측: 우리에선 balanced 파산 리스크로 기각. 연구 후보 |
| **④ 리지+GBM/GLM 앙상블** | **thislifehea** (있던 0.70) | 릿지와 GBM을 score·cost 둘 다 평균 | 실측: dev 과적합, 우리 Train-CV에선 기각 |
| **⑤ 참조 기반 + 마진 튜닝** (hash n-gram + ridge) | leestand, jbk-01, hwkim, difficcd 등 대다수 | 공식 hash_regex ridge + 안전계수 dev 튜닝 | 우리가 이미 같은 구조로 우위. 통제군 |
| **⑥ 보안·결정성 공학** | Diwoni, Seosamo, yuJunhyk | ID/순서 불변, arm64 런타임 측정, 티어별 시간 예산 | 우리도 완비 |

**핵심 통찰 1:** 상위권의 실질 점수 차는 **표현(representation)** 에서 온다.
해시 n-gram → 의미 임베딩이 가장 큰 단일 점프(+0.023). Seosamo마저 임베딩을
런타임에 못 넣고(150s>90s) TF-IDF로 물러났다.

**핵심 통찰 2:** Diwoni만 **런타임 예산 안에서 임베딩을 성공**시켰다(fine-tuned
small E5, 49~64s). 임베딩의 "점수 베네핏"은 잘 알려졌지만, **제약 하에서의 배포
공학이 곧 진입장벽**이다.

## B. 우리가 실측으로 이미 검증한 것 (한계선)

| 아이디어 | 결과 | 기록 |
| --- | --- | --- |
| GBM 비용헤드 | dev 안 오름 | D8, note §3 |
| 점수헤드 앙상블 | dev+0.0036이지만 Train-CV 하락·게이트 불통 | D8 §3b |
| E5 임베딩 naive 추가 | dev 0.675~0.681 (이득 없음) | D8 §6 |
| regret 가중 점수학습 | dev 악화 (fast 붕괴) | D8 §7 |
| token-cost 비용헤드 | dev+0.0016이지만 balanced 파산 | D8 §8 |
| 가족특화를 fast/bal로 확장 | Train-CV 하락 | D8 §9 |

**즉, "이미 강하게 튜닝된 우리 ridge+게이트 구조에 방식을 겉붙이는" 것만으로는
점수가 안 오른다.** 상위권 이점은 **표현을 바꾸고, 그에 맞춰 전체 학습·배포를
재튜닝하는 총공**에서 나온다.

## C. 향후 연구 로드맵 (개인 연구 후보)

다음 연구는 **경쟁자의 아이디어를 우리 실측의 한계와 결합**해 설계한다.
각각 "실측 근거"와 "열린 질문"을 명시.

### 연구 1: 경량 의미 임베딩 + 기존 히스토그램 하이브리드 (최우선)
- **근거**: Diwoni +0.023은 임베딩이고, 우리 naive 추가(§6)가 안 오른 건
  *표현만 바꾸고 나머지(헤드 튜닝, safety, 배치)를 안 재튜닝*했기 때문으로 추정.
- **연구**: E5-small 임베딩(384d)을 *새 score 헤드의 입력*으로 쓰되,
  ① fine-tune on score target (not just regress on pooled embed)
  ② 임베딩+해시를 함께, 안전계수를 임베딩에 맞게 재보정
  ③ ONNX int8/fp16 + 연산 배치로 90s 예산 안 확보
- **열린 질문**: 1,760행에 fine-tune이 과적합 안 되게 하는 손실·정규화는?
  임베딩이 문제 계열 일반화(leave-one-family-out)를 분리해주나?

### 연구 2: regret 가중 + per-attempt 이진 분류 (Seosamo 방식, 독립 모델로)
- **근거**: 우리 ridge에선 악화했지만(§7), Seosamo는 LightGBM 승률 클수로 체감.
  원인은 "ridge가 원점수 target을 선호" vs "이진 분류 + regret 가중은 승률 순위에
  최적" 의 차이일 가능성.
- **연구**: 전용 승률 분류기(LogReg→GBDT→임베딩)를 ridge와 **독립 모델**로 두고,
  스태킹(승률 순위 신호)으로 결합. regret 가중으로 경계 문항에 학습 집중.
- **열린 질문**: 승률 `predict_proba`를 allocator의 유틸(점수)로 쓰면 등급별
  점수와 어긋나는 보정이 필요한가? (Seosamo가 라그랑지 bisection으로 우회)

### 연구 3: 출력토큰 분위 회귀의 안전화 (cost tail)
- **근거**: token-cost(§8)는 dev+0.0016이지만 balanced 파산. 이유는 우리가
  per-source risk_quantile을 "총비용"에 붙인 반면, 토큰 유도 cost의 상대오차 분포가
  달라 balanced를 과소가격했기 때문으로 추정.
- **연구**: 토큰 유도 cost에 **계열별 편향보정 + 좀 더 보수적 프리미엄 전용
  risk_quantile**을 재설계하여, balanced 파산을 막으면서 정확도 이득 유지.
- **열린 질문**: 출력토큰 로그분포의 heavy tail을 quantile 대신 EVT/팽창 분포로
  모델링하면 예산 상한을 더 정확히 잡나?

### 연구 4: 프레임워크 수준 — 라우팅을 MaaS 게이트웨이로
- **근거**: 비용민감 라우팅은 이 대회만의 문제가 아님(우리 로드맵에 이미 있음).
- **연구**: 이 라우터를 API 게이트웨이 형태로 일반화 — 요청 스트림에서
  예측→할당→모니터링. 동적 예산(요청량 변동), 지연 예산, 다중 정책.
- **열린 질문**: 라우팅 결정의 확률적 래그(실측 vs 예측 비용 보정)를 온라인으로
  업데이트하는 밴디트 구조는?

### 연구 5: 일반화 진단 방법론 (파레토 프론티어 + 파산 게이트)
- **근거**: 우리가 도입한 파레토 판정 프레임이 실질 이득이었다.
- **연구**: '점수 대 파산위험' 프론티어를 공식적으로 정형화 — 파산이 숨은
  분포에서 실현되면 가중 0.3~0.4가 사라지는 비대칭 손실을 감안한 **EV 판정**을
  실험 1등 기준으로 삼는 프레임워크.
- **열린 질문**: leave-one-family-out vs 실제 숨은 분포 이동의 갭을 줄이는 보정?

## D. 요약 (연구에 남길 것)

1. **표현(representation)이 점수의 큰 갈림길** — 해시 → 임베딩이 +0.023.
   앞으로는 임베딩 학습을 우선.
2. **제약 하 배포(런타임 90s/2GiB)가 진입장벽** — 임베딩 ONNX 최적화가 차별화.
3. **방식을 '겉붙이기'하면 안 오른다** — 표현·헤드·안전·배치 전부 재튜닝 필요.
4. **파레토 EV 판정 프레임**이 우리가 이긴 요인 — 이를 방법론으로 승격.
5. **안전=파산게이트는 우리 경쟁우위의 원천** — 위험을 정량화해 최적점을 고른 것.

본 문서는 경쟁자 공개 정보와 우리 자체 실측만으로 작성했다. 경쟁자 코드는
복사하지 않았고, 대회 규칙(라이선스·독창성)을 지킨다.
