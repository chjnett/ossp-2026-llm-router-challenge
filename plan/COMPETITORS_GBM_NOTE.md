# 경쟁자 정황 검증 + GBM 비용헤드 실험 판정 (2026-08-19)

공개 저장소의 최신 실험 기록을 확인해 두 경쟁팀의 "릿지+GBM 앙상블"이 실제로
우리보다 나은지 검증했다. 그리고 우리 베이스(T38)에 그 메커니즘을 **복제해**
dev 점수에 미치는 영향을 직접 측정했다. 경쟁사 실험 코드는 복사하지 않고
아이디어(hashed 특징 위 비선형 비용 회귀)만 적용했다.

## 1. 이 각각 비교의 전제

우리의 "Dev 0.683892"는 `data/materialized/dev`(공식 880문항)에서의 측정이고,
경쟁팀도 같은 공식 dev를 쓴다(각각 `data/dev/outcomes.json` 880문항). 둘 다
Train(1760)으로 학습 → 공식 dev로 측정하므로 절대 비교가 성립한다.

  최종 채택은 관측 08-14 기준 H(0.695994)였다. 08-19 기준 새 채택 여부는 미확인.

- **진짜 위협은 thislifehea.** 우리가 공식 baseline조차 dev에서 못 이긴다
  (0.6839 vs 0.6954). 단 이 절대치는 "숨은 채점셋은 dev보다 비싸다(공식 baseline
  Premium 3.985→4.2 초과)" 는 사전검증으로 보정돼야 하며, 더 높은 dev 품질이
  위험 보정 후에도 그대로 이기는지는 불확실.

## 3. GBM 비용헤드 실험 (우리 T38 복제)

`experiments/probe_gbm_costgate.py`로 먼저 Train-OOF 로그비용 RMSE를 재고,
`GBMHashRidgeCost`(`gbm_hash_ridge`, `heads.py`)로 전체 파이프라인을 돌렸다.

**OOF 로그비용 RMSE (낮을수록 좋음, Train 5-fold):**
- ridge OOF: 총 0.681
- HistGBM OOF: 총 **0.568** (훨씬 좋음)
- 릿지·GBM 평균(w=0.7): 0.576

**그런데 dev final_score (공식 dev, 같은 T38 게이트·할당·스케어헤드):**
- ridge (현 챔피언): **0.6814**
- GBM 전용 (w=1.0): 0.6773 ▼
- GBM 앙상블 w=0.3/0.5/0.7: 0.6799/0.6788/0.6799 ▼ (전부 ridge 미만)
- 강한 GBM(ml=31,it=150): 0.6822 ≈ (우열 아님)
- Premium만 GBM: 0.6806 ▼

**판정: GBM 비용헤드를 우리 T38에 끼워도 dev 점수가 오르지 않는다.** 단일
모델 OOF RMSE는 GBM이 더 좋지만, 예산 사용량이 내려가고(프리미엄 3.65→3.41)
가격 배율이 달라져 할당이 더 보수적으로 변해 점수가 깎인다. 우리의
risk_quantile/unseen/calibration 머신이 이미 비용 불확실성을 가격에 넣고 있어
GBM이 추가하지 못한다. D8: **기각(추가 실험 없이).**

**왜 thislifehea는 이득을 봤나:** 그들의 +0.0056은 비용헤드뿐 아니라 **score
헤드까지 포함한 릿지+GBM 평균 앙상블**(K)과 그에 맞춘 dev 안전계수 재탐색에서
나왔다. 아래 3b에서 이 score 앙상블을 우리 규율(Train-CV)로 실측한 결과
dev에서만 이기고 Train-CV에선 모두 져, 그 이득은 **dev 과적합**임을 확인했다.

## 3b. 점수헤드 앙상블 실측 (their 실제 메커니즘을 우리 규율로 판정)

thislifehea 실험 기록(I→K)을 읽으니 그들의 +0.0056은 **score 헤드까지 포함한**
릿지+GBM 평균이었다(K). 우리는 비용헤드뿐 아니라 **점수헤드 앙상블**도 공식
dev와 Train-CV 둘로 직접 실측했다(`experiments/probe_score_ensemble.py`,
t39-score-blend-a100-w06).

- **Dev에서는 이긴다:** 튜닝 점수헤드(alpha=32000)를 alpha=100 릿지와 60/40으로
  블렌드하면 dev **0.6814 → 0.6850 (+0.0036)**, 프리미엄 예산도 3.65→3.03로 더
  안전해진다(여러 대체 헤드·가중치 스윕 최고).
- **하지만 승격 기준인 Train-CV에선 전부 진다:** 블렌드 스윕 전체가 T38의
  Train-CV(0.6663) 대비 **-0.0002~-0.0049**. t39 CV 가중 0.6545(▼0.0118).
- **판정: dev 이득 = dev 과적합.** 이는 우리가 이전에 독립적으로 도달한
  "0.69→0.71 온 dev 반복 최적화는 우승 신호가 아니라 과적합 신호"라는 경고를
  그대로 확증한다. 우리 승격 규칙(RULES D7, Train-CV)에서는 블렌드 score를
  **기각**. D8.

**즉 thislifehea의 앙상블 이득은 dev 기반 안전계수·헤드 선택의 dev 과적합에서
온 것으로, 우리의 Train-CV 규율에선 재현되지 않는다.** 그들의 0.70+가 숨은
채점셋에서 그대로 나온다는 보장이 없으며, 실제로 공식 baseline이 "dev 3.985 →
채점셋 4.2 초과"로 비싸진 전례가 있다.

## 5. 결론과 권고 (2026-08-19, 두 메커니즘 모두 실측 완료)

- **thislifehea의 두 레버(비용헤드 GBM, 점수헤드 앙상블)를 우리 T38에 복제해
  직접 측정했고, 둘 다 승격 기준 Train-CV에서 기각이다.** 비용헤드는 dev에서조차
  안 오르고, 점수헤드 앙상블은 dev에서 +0.0036 오르되 Train-CV에서 -0.0002~
  -0.0049(전부 하락)로 **dev 과적합**임을 확인.
- **결론:** 상대의 점수는 dev 기준 튜닝에서 나온 것으로, 우리 규율(Train-CV +
  파산 게이트)과는 근본적으로 다르다. 우리가 그들의 dev(0.70대)에 못 미치는 건
  우리가 dev를 안 쓰기 때문이며, 이는 **강점이지 약점이 아니다.** 공식 baseline의
  "dev 3.985 → 채점셋 4.2" 전례가 숨은 셋이 dev보다 비싸다는 근거를 준다.
- **현 방침 유지:** T38(제출·이미지 완료, 안전 여유 + premium 3.65, 스트레스
  0.22%)을 동결. 남은 시간은 마진·게이트 극소 튜닝(Train-OOF 판정)과
  보고서·데모 마감에 쓴다. "0.69~0.70 최고점 추격"은 dev 과적합 리스크를 안으면서
  Train-CV 수익이 전혀 없어 **기각 확정**.

## 6. 임베딩(E5) 실측 — Diwoni(+0.023) 쫓기 판정 (2026-08-26)

Diwoni의 정직한 train-only 0.7068은 **fine-tuned E5 의미임베딩 + Qwen 교사증류 +
ONNX 런타임검증(49~64s)**에서 나온다. 우리 해시 구조로는 격차의 원인(의미임베딩)을
따라잡을 수 있는지 직접 실측했다(`experiments/probe_embed_score.py`).

- **실행시 임베딩 속도는 OK**: E5-small로 Dev 880문항 6.4s, Train+Dev 2640 추정
  ~20s — 90s 등급 예산 안. Diwoni의 런타임 49~64s 짐.
- **하지만 우리 파이프라인에 naive로 끼우면 이득이 안 난다**: [해시+E5] vs
  [해시만]을 동일 naive ridge로 비교 → dev 0.675~0.681 (우리 튜닝 헤드 0.6814
  못 넘김, 기능을 대체하니 비교가 억울). Diwoni의 이득은 **fine-tuning + 교사증류 +
  스태킹**까지의 총공(總功)에서 나오고, 1760행에 naive E5+ridge는 과적합.
- **판정: E5 임베딩을 "단순히 추가"해선 우리를 올릴 수 없고, Diwoni 수준의 이득은
  fine-tuning+교사증류(+런타임 공학)가 필요하다.** 마감 하루 전에 그걸 안전하게
  완성할 실현 경로가 없고, 검증된 t43(0.6844)을 그걸 위해 도박할 수 없다. **D8.
  해시+게이트 구조의 최선은 t43 동결이며, 임베딩은 접지 않는다.**

## 7. 경쟁자 독특 아이디어 추가 실측 — 전부 기각 (2026-08-26)

클론 18개에서 우리가 안 쓴 독특 메커니즘을 발굴해 각각 실측했다.

- **Seosamo regret-weighted win-probability score 학습**: 문항별 가중치
  `w = best_score - 2nd_score`(선택이 결과를 갈리는 문항에 학습 집중) +
  per-attempt 이진 exploded target. 우리 ridge 점수헤드에 regret 가중만 적용
  → dev 0.6814→0.6777(**악화**, fast 0.6523→0.6409 붕괴). alpha=32000 릿지는
  원점수 target을 선호. **기각.**
- Seosamo output-token quantile 비용모델 = 우리 `risk_quantile`과 동일 사상(이미
  사용). 새것 아님.
- Diwoni 문제군 비용보정 = 우리 `unseen_risk_boost`/family calibration과 동일
  사상. 새것 아님.
- Diwoni/Seosamo가 기각한 것(GLM 생성수, 비선형 GBM, 문제군 전문가)도 우리가
  이미 동일한 이유로 기각.

**요약**: 해시+게이트 구조에서 "새 아이디어를 끼워 이득"을 주는 것은 이번 스윕
(비용 GBM / score 선택 / E5 임베딩 / regret 가중)에서 **하나도 없다.** 리더
(Diwoni)의 이점은 의미임베딩+교사증류 총공이며, 이는 마감 하루 전에 안전 재현할
경로가 없다. **t43(0.6844 검증) 동결이 정답.**
