# 결과보고서 원고

공식 양식(osscontest.kr에서 받는 한글/Word 파일)에 옮겨 넣을 내용이다.
본문 5쪽 이내, 첫 쪽의 작성 안내와 회색 안내 문구는 제출 전에 삭제한다.
파일명은 `2026 오픈소스 개발자대회 결과보고서_접수번호(팀명)`.

**제출 전에 채워야 하는 칸은 `⬜`로 표시했다.**

---

## 1. 프로젝트 개요

프롬프트 하나마다 세 모델 중 하나를 고르는 라우터다. 모델을 부르지 않고
**프롬프트 본문과 등급만 보고** 결정하며, 등급별 비용 상한 안에서 정답률
합계를 최대화한다.

| 모델 | 성격 |
| --- | --- |
| `ax31-light` | 가장 싸다. 예산 기준선 |
| `ax31` | 중간 |
| `axk1-think` | 가장 비싸고 정확하다 |

세 등급은 "항상 최저가로 돌렸을 때의 총비용"에 배수를 곱한 예산을 준다.

| 등급 | 예산 배수 | 최종 점수 가중치 |
| --- | ---: | ---: |
| Fast | 1.25배 | 0.40 |
| Balanced | 2.00배 | 0.30 |
| Premium | 4.00배 | 0.30 |

## 2. 문제의 성격

공개 Dev 880문항을 공식 채점기로 재면 문제가 분명해진다.

| 전략 | 정답률 | 가중 최종 점수 | 비고 |
| --- | ---: | ---: | --- |
| 항상 `axk1-think` | **0.8264** | **0.0000** | 세 등급 모두 예산 초과 |
| 항상 `ax31` | 0.6918 | 0.2075 | Fast·Balanced 초과 |
| 항상 `ax31-light` | 0.6193 | 0.6193 | 항상 통과 |
| **제출 라우터** | — | **0.6491** | 세 등급 통과 |

품질 천장은 0.8264인데 살 돈이 없다. **예산을 한 번이라도 넘기면 그 등급은
0점**이므로, 이 문제는 "좋은 모델 고르기"가 아니라 **"제한된 예산으로 무엇을
살지 고르기"**다.

## 3. 접근

세 단계로 나눈다.

**(1) 예측.** 프롬프트에서 17개 특징과 9개 계열(수학·코드·논리·객관식 등)을
뽑아, 모델별 정답 확률과 토큰 비용을 능형회귀로 예측한다. 비용은 로그
공간에서 적합한 뒤 Duan smearing으로 되돌리고, 합계 편향을 따로 보정한다.

**(2) 배분.** 문항마다 "이 모델로 올리면 점수가 얼마 오르고 비용이 얼마
드는가"를 계산해 **비용 대비 점수 증가율(ROI)** 순으로 예산이 닿는 데까지
산다. 각 문항의 (비용, 점수) 점들의 **상단 볼록포**만 남기므로 중간에 손해인
선택이 끼어들지 않는다.

라그랑주 승수를 이분 탐색하는 방식과 답이 같으면서 1.7배 빠르고, **순서에
무관함이 자명하다.** 평가에서 문항 ID를 전부 바꾸고 순서를 섞어 다시 돌리는
감사가 있으며, 결과가 하나라도 다르면 자동 채점이 멈춘다.

**(3) 안전.** 비용은 예측값이라 실제와 다르다. 예측이 낮게 나오면 예산을
넘겨 0점이 된다. 그래서 상향 편향(`z`)과 배치 크기에 따른 여유
(`h − k/√n`)를 두고, 6종 분포 변화 시나리오 × 문항 수 3종 × 등급 3종으로
**36,000회 모의 실행**해 초과가 0회인 설정만 챔피언으로 올린다.

## 4. 결과

공개 Dev 880문항, **컨테이너가 낸 출력을 공식 채점기에 넣은** 값이다.

| 등급 | 점수 | 예산 사용 | 한도 |
| --- | ---: | ---: | ---: |
| Fast | 0.6238 | 1.017 | 1.25 |
| Balanced | 0.6460 | 1.140 | 2.00 |
| Premium | 0.6860 | 1.665 | 4.00 |
| **가중 최종** | **0.6491** | | |

교차검증 0.6349. 파산 게이트 36,000회 초과 0회. 테스트 350개.

정직하게 적으면, 점수 상승의 **대부분은 모델링 아이디어가 아니라 구현 결함을
고친 데서 나왔다.** 임베딩 도입, 동점 탐지기, 확률 제약 배분 등 네 갈래는
모두 효과가 없거나 가설이 반증되어 버렸다. 반면 중복 프롬프트가 갈라져
배분되던 문제, 로그 예측의 외삽 폭주, 합계 편향, 교차검증이 폴드마다 예산을
쪼개던 문제를 고친 것이 실제 점수를 올렸다.

안전 손잡이도 하나씩 실측해 **8개에서 6개로 줄였다.** 계열별 ROI 차단과 K1
비용 상한은 켜도 꺼도 결과가 완전히 같았다 — 배분기가 이미 ROI 순으로
고르므로 비싼 선택이 애초에 뽑히지 않았다.

## 5. 실행과 재현

이미지는 네트워크 없이, 읽기 전용 루트 파일 시스템에서, UID 65532로 돈다.
학습은 하지 않고 이미지에 굳혀 넣은 계수만 읽는다.

| 항목 | 측정값 | 한도 | 사용률 |
| --- | ---: | ---: | ---: |
| 압축 계층 합계 | 63.4 MiB | 1024 MiB | 6.2% |
| rootfs 겉보기 크기 | 195.8 MiB | 2048 MiB | 9.6% |
| 실행 시간 (2,640문항, 등급당) | 2.1초 | 90초 | 2.3% |

측정은 공식 도구(`router-measure-image`, `tools/check_runtime.py`)로 했다.
제출 절차 전체는 저장소의 `plan/RELEASE.md`에 있다.

어떤 예외도 등급을 죽이지 않도록, 프로세스 시작 직후 유효한 결정을 먼저
확보하고 예측이 실패하면 그대로 낸다. 시간 예산의 60%가 지나면 계산을 접는다.

## 6. 필수 기재 항목

### 프로젝트 등록 URL

```
⬜ https://github.com/chjnett/ossp-2026-llm-router-challenge/tree/<40자리 커밋 SHA>
```

`submission-ossp-skt.json`을 담은 커밋의 스냅샷이어야 한다. 브랜치 URL이나
움직일 수 있는 기본 브랜치 URL은 안 된다.

### 이미지

```
⬜ <레지스트리>/ossp-router@sha256:<64자리>
```

태그가 아니라 전체 다이제스트. `linux/arm64`.

### SBOM

저장소의 [`container/sbom.cdx.json`](../container/sbom.cdx.json).
CycloneDX 1.5, 구성요소 108개 (Debian 105, Python 2, 참가자 1).

이미지 안의 dpkg 데이터베이스와 Python dist-info를 직접 읽어 만든다. 기반 OS
패키지의 라이선스 근거는 이미지 안 `/usr/share/doc/<패키지>/copyright`에
105개 전부 보존되어 있다.

### AI 모델 활용·라이선스

```
해당 없음 — 실행 이미지에 AI 모델을 탑재하지 않음
```

라우터는 능형회귀 계수(148 KB JSON)만 사용한다. 신경망 가중치, 사전학습
모델, 토크나이저를 포함하지 않는다. 실행 중 어떤 모델도 호출하지 않는다.

### AI 코딩 도구 사용 범위

```
⬜ 아래 내용을 확인하고 조정할 것
```

Anthropic Claude Code(Claude Opus)를 사용했다. 사용 범위는 다음과 같다.

- 설계 검토, 구현, 테스트 작성, 문서 작성 전반
- 실험 설계와 결과 해석
- 최종 판단, 실험 채택 여부, 제출 결정은 참가자가 했다

생성한 코드는 전부 참가자가 검토했으며 350개 테스트와 공식 채점기로 검증했다.

### 데모 영상 URL

```
⬜ <영상 URL>
```

담을 내용 제안 (2~3분):
1. `docker run`으로 세 등급을 돌려 `submission.json`이 나오는 것
2. 공식 채점기로 세 등급 점수와 예산 사용률을 보이는 것
3. `tools/verify_release.py`가 9개 항목을 확인하는 것
